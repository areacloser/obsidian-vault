## 2. 程序流程与语句分类（§4.1，课件第4–5页）

### 2.1 三种基本控制结构

课件把程序执行流程归纳为：

| 基本结构 | 含义 | 典型 C 语言机制 |
|---|---|---|
| **顺序结构** | 依次执行操作 | 普通语句顺序执行 |
| **选择结构** | 按条件从多个执行路径中选择 | `if`、`if-else`、`switch` |
| **循环结构** | 根据条件反复执行一段操作 | `while`、`do-while`、`for` |

课件使用“单一入口和单一出口”介绍结构化程序设计：优先用顺序、选择、循环组合解决问题，使控制流程便于阅读与验证。

> [!note] 补充理解
> 这里的“单一出口”用于说明结构化控制流的教学思想，不是说每个 C 函数只能书写一条 `return`。`return`、`break` 等的具体控制效果会在后续笔记中详细讨论。

### 2.2 课件中的语句分类

课件将 C 程序中的构造大致归纳如下：

| 类别（按课件） | 形式或关键字 | 举例 |
|---|---|---|
| 声明相关 | 变量声明、类型定义、函数原型等 | `int x;`、`void f(void);` |
| 表达式语句 | `表达式;` | `x += 2;`、`printf("ok");` |
| 复合语句 | `{ ... }` | `{ int t = x; x = y; y = t; }` |
| 选择语句 | `if`、`switch` | `if (x > 0) ++x;` |
| 循环语句 | `while`、`do while`、`for` | `while (x > 0) --x;` |
| 跳转语句 | `break`、`continue`、`return`、`goto` | `return 0;` |
| 标号语句 | `标识符:`，以及 `case`、`default` | `case 1:` |

> [!note] 标准辨析：声明与语句不是同一语法类别
> 在 ISO C 的语法层面，`int x;` 属于**声明（declaration）**，不应简单等同于“表达式语句”。C99 起，复合语句的块项目可以包含声明和语句，并允许二者交错书写。课件采用更便于教学的总分类，考试术语可优先按老师的表述识别。

## 3. 表达式语句与空语句（§4.2，课件第6页）

### 3.1 表达式与表达式语句的区别

表达式语句的一般形式：

```c
[表达式];
```

方括号表示表达式可选，并不是 C 代码实际包含方括号。

| 表达式 | 表达式语句 |
|---|---|
| `x = y + 1` | `x = y + 1;` |
| `x += y` | `x += y;` |
| `i = j = k` | `i = j = k;` |
| `printf("hello")` | `printf("hello");` |
| `scanf("%d", &x)` | `scanf("%d", &x);` |

执行表达式语句时，表达式会被求值；其值通常被丢弃，但运算带来的**副作用**（如赋值、函数输出）仍然生效。

```c
int x = 1;
x + 2;    // 计算表达式后丢弃结果，x 仍为 1
x = x+2;  // 赋值有副作用，x 变为 3
```

> [!warning] `=`、`==` 与“表达式值被丢弃”
> `if (x = 3)` 在语法上可以成立：它先给 x 赋值，再把赋值表达式的值 3 当作条件（真）。这不等于 `if (x == 3)`。编译器可能给出警告，但不能把所有赋值条件都认定为语法错误。

### 3.2 空语句 `;`

空语句是只含一个分号的语句，不执行实质操作：

```c
;
```

常见陷阱：

```c
if (x > 0);   // if 的受控语句就是这个空语句
    ++y;      // 无论 x 是否大于 0，都会执行
```

**和 `{}` 区分**：`;` 是空表达式语句，`{}` 是空复合语句；两者都可以“不执行具体操作”，但属于不同语法构造。

## 4. 复合语句与块作用域（§4.3，课件第7–10页）

### 4.1 复合语句的结构

```c
{
    int temp = 0;  // 声明
    temp += 1;     // 语句
}
```

一对 `{}` 组成**复合语句（compound statement）**，也称为一个**块（block）**。它在语法上作为一条语句使用，内部却可以容纳多条声明和语句。

常见用途（课件第10页）：

1. 作为 `if` 分支或循环体，将多条操作组织成一条复合语句。
2. 改变 `if-else` 的语法配对方式。
3. 声明仅在特定范围中需要的临时变量。

> [!note] 版本差异
> C90 的传统写法要求在块开头放置局部声明；从 **C99** 起，允许在同一块中交错书写声明和语句。课程课件示例主要使用声明在前的写法。

### 4.2 作用域与变量遮蔽

**课件原例（第9页，整理排版但不改变逻辑）：**

```c
#include <stdio.h>

int main(void)
{
    int a = 0, b = 1;
    {
        int a = 1;
        printf("a=%d\n", a);
        printf("b=%d\n", b += 1);
    }
    printf("a=%d\n", a);
    printf("b=%d\n", b);
    return 0;
}
```

**输出：**

```text
a=1
b=2
a=0
b=2
```

逐项分析：

| 执行位置 | `a` 指向哪个对象 | `b` 的情况 | 结果 |
|---|---|---|---|
| 进入外层块 | 外层 `a=0` | 外层 `b=1` | — |
| 内层声明 `int a=1;` | 新建内层 `a=1`，遮蔽外层 a | 未声明新的 b | — |
| 内层第一个 `printf` | 内层 `a` | — | `a=1` |
| 内层第二个 `printf` | — | `b += 1` 修改外层 b | `b=2` |
| 离开内层块 | 内层 a 不再可见 | 外层 b 保留为 2 | — |
| 外层两个 `printf` | 外层 `a=0` | 外层 `b=2` | `a=0`、`b=2` |

> [!important] 易考结论
> - **同名变量遮蔽**：内层声明的同名标识符会在其可见范围中遮蔽外层标识符。
> - **查找名字不等于修改对象**：内层声明 `a` 不会修改外层的 `a`。
> - **找不到内层同名变量就向外层查找**：内层中的 `b` 是外层 `b`。
> - 变量在块外不可见，不代表该变量所在的所有其他对象都发生了变化。

### 4.3 课件第8页的作用域题

课件中的内层块声明 `int a, b, t;` 后，块外的 `printf("%d%d", a, b);` 无法访问这些块内声明的 `a`、`b`，因此若外层未另行声明它们，应在编译阶段得到未声明标识符相关诊断。

> [!warning] 课件中的另一个错误
> 第8页内层示例写作 `scanf("%d%d", a, b);`，这里对于 `int a, b` 应传入 `&a, &b`。缺少 `&` 并不属于“作用域”问题，而是 `scanf` 参数类型与地址要求不匹配，若照原样执行会产生未定义行为。参见 [[08 字符输入输出与格式化输入输出]]。

### 4.4 例 4.1：利用临时变量交换整数

**课程版本（课件第10页，保留主要代码）：**

```c
#include <stdio.h>

int main(void)
{
    int a, b;
    printf("input a, b:\n");
    scanf("%d%d", &a, &b);
    {
        int t;
        if (a > b) {
            t = a;
            a = b;
            b = t;
        }
    }
    printf("a=%d, b=%d\n", a, b);
    return 0;
}
```

假设输入 `19 16`，输出 `a=16, b=19`。

这里嵌套的块并非交换两个数的必要条件，作用是**演示局部临时变量 `t` 的可见范围**。

> [!warning] 不建议用算术代替临时变量
> 课件旁边还展示了 `a=a+b; b=a-b; a=a-b;` 的交换思路。若 `a+b` 超出 `int` 可表示范围，会触发有符号整数溢出的未定义行为。优先使用临时变量交换，见 [[05 运算符与表达式]]。

**改进版本（与课程版本分开）：**

```c
#include <stdio.h>

int main(void)
{
    int a, b;
    if (scanf("%d%d", &a, &b) != 2) {
        fputs("invalid input\n", stderr);
        return 1;
    }

    if (a > b) {
        int t = a;
        a = b;
        b = t;
    }
    printf("a=%d, b=%d\n", a, b);
    return 0;
}
```

这个版本检查了输入是否成功，去掉无必要的外层独立块；**考试若要求复现课件示例，仍优先理解并保留课程版本**。

## 5. `if` 与 `if-else`（§4.4.1，课件第11–14页）

### 5.1 语法和执行流程

```c
if (表达式)
    语句1;
```

```c
if (表达式)
    语句1;
else
    语句2;
```

注意：上述 `语句1;`、`语句2;` 是示意写法。实际受控体可以是一条表达式语句，也可以是 `{ ... }` 复合语句或其他合法语句；**不是在任何受控语句之后都再补一个分号**。

- 条件的值等于 `0`：假。
- 条件的值不等于 `0`：真。
- `if-else` 在两条路径中最多执行一条分支；只有 `if` 而条件为假时，分支体不执行。

> [!note] 标准辨析：“表达式是逻辑类型”只是课件的教学说法
> ISO C 允许 `if` 的控制表达式具有**标量类型**（如算术类型、指针类型），并不要求必须写成 `_Bool`。`if (5)` 为真、`if (-2)` 为真、`if (0)` 为假。数组或结构体对象不能直接作为一个结构体值来充当 `if` 条件（数组表达式在适当上下文通常会转换为指针）。

### 5.2 花括号决定分支范围

```c
if (x > 0)
    ++a;
    ++b;
```

这里只有 `++a;` 受 `if` 控制，`++b;` 总会执行；缩进不会影响 C 语言的语法。

```c
if (x > 0) {
    ++a;
    ++b;
}
```

这里两条操作都由 `if` 控制。

> [!warning] 典型笔试陷阱
> 不能只根据缩进判断条件语句范围，应首先辨认 **`{}`、分号及实际语法结构**。

### 5.3 嵌套 `if` 的 `else` 就近匹配原则

课件第13页强调：在不存在花括号等结构改变配对的情况下，`else` 与**最近的、尚未配对的 `if`** 匹配。

```c
if (a > 0)
    if (b > 0)
        puts("A");
    else
        puts("B");
```

等价于：

```c
if (a > 0) {
    if (b > 0)
        puts("A");
    else
        puts("B");
}
```

当 `a <= 0` 时，**没有输出**，因为 `else` 属于内层 `if`，不是外层 `if`。

如果希望 `else` 属于外层，则必须使用花括号改变语法结构：

```c
if (a > 0) {
    if (b > 0)
        puts("A");
} else {
    puts("B");
}
```

> [!note] 对“嵌套条件之间是逻辑与”的限定
> 课件第12页使用这一表述描述进入多个连续真分支的条件：要进入最内层真分支，需同时满足外层与内层条件。但是不能机械概括为“所有嵌套 `if` 均等同 `&&`”：嵌套结构还可能包含 `else`，不同路径的组合条件也不同。

### 5.4 `else if` 多分支结构

```c
if (条件1) {
    // 路径 1
} else if (条件2) {
    // 路径 2
} else if (条件3) {
    // 路径 3
} else {
    // 以上条件均不满足
}
```

这是 `else` 分支中继续包含一个 `if`，不是名为 `else if` 的新关键字。条件从前往后检查，**首次命中的分支执行，之后的分支不再检查**。

| 结构 | 执行特点 |
|---|---|
| `if (A) ...; if (B) ...;` | 两次 `if` 独立判断；可以同时执行两个受控体 |
| `if (A) ...; else if (B) ...;` | 第二次判断仅发生在 A 为假时；最多选中一条分支 |

### 5.5 例 4.2：学生成绩分级

课件给定的划分标准（第14页）：

| 成绩 x | 等级 |
|---|---|
| `90 <= x <= 100` | `excellent` |
| `80 <= x < 90` | `good` |
| `60 <= x < 80` | `middle` |
| `0 <= x < 60` | `bad` |
| `x < 0` 或 `x > 100` | 输入错误 |

> [!important] 边界值必须单独检查
> `0`、`60`、`80`、`90`、`100` 均有对应区间，不能因为条件书写不准确而漏掉。`90 <= x <= 100` 是数学区间写法，在 C 中**不能直接**用 `90 <= x <= 100` 表示相同逻辑，应写为 `x >= 90 && x <= 100`。

**课程版本（保留 `else if` 判定顺序，排版规范化）：**

```c
#include <stdio.h>

int main(void)
{
    float x;
    scanf("%f", &x);
    if (x > 100 || x < 0)
        printf("input error!\n");
    else if (x >= 90)
        printf("excellent!\n");
    else if (x >= 80)
        printf("good!\n");
    else if (x >= 60)
        printf("middle!\n");
    else
        printf("bad!\n");
    return 0;
}
```

为什么后面的分支不需要再写上界？例如执行到 `x >= 80` 时，`x >= 90` 已经判定为假，所以隐含 `x < 90`。

**改进版本（输入检查单独处理）：**

```c
#include <stdio.h>

int main(void)
{
    float x;
    if (scanf("%f", &x) != 1 || !(x >= 0.0f && x <= 100.0f)) {
        puts("input error!");
        return 1;
    }

    if (x >= 90.0f)
        puts("excellent!");
    else if (x >= 80.0f)
        puts("good!");
    else if (x >= 60.0f)
        puts("middle!");
    else
        puts("bad!");
    return 0;
}
```

改进版还会拒绝 NaN（它与任何通常的大小比较均不成立），但这一点属于浮点特殊值补充，不是课件明确考点。

## 6. `switch` 选择语句（§4.4.2，课件第15–19页）

### 6.1 语法与基本规则

```c
switch (整型表达式) {
    case 常量表达式1:
        语句序列1
        break;
    case 常量表达式2:
        语句序列2
        break;
    default:
        默认语句序列
}
```

**执行过程：**

1. `switch` 控制表达式只求值一次。
2. 找到与其值匹配的 `case` 标签；若没有匹配项，转到 `default`（如有）。
3. 从匹配的标签处**进入**，此后按语句的书写顺序执行。
4. 遇到属于该 `switch` 的 `break` 就跳出；没有 `break` 则可能贯穿后面的标签，直至离开 `switch` 主体。

注意：`case` 标签不是每执行到一次就重新判断一次的 `if`。

> [!important] 必考的三个事实
> - `switch` 控制表达式必须具有**整数类型**；实际比较前对控制表达式执行整数提升。
> - `case` 后面必须是**整数常量表达式**；同一 `switch` 中转换后不能有相同的 `case` 值。
> - `default` 可省略，可以出现在任何位置；它只是无匹配时的**入口**，并不自动结束流程。

### 6.2 `case` 与变量、常量的关系

```c
#define K 3
const int n = 3;
enum { E = 3 };

int x = 3;
switch (x) {
    case K:           /* 合法 */
        break;
    // case E:        /* E本身是合法的case常量，但此处与K重复 */
    //     break;
    // case n:        /* C11/C17不合法：const对象不是整数常量表达式 */
    //     break;
}
```

这里 `case K` 是可编译的合法示例。若将 `case E` 同时取消注释，则两个标签的值均为 3，编译器必须给出诊断；`case n` 则在 C11/C17 中不符合整数常量表达式要求。

> [!warning] 语法题易错
> `switch (2.5)` 不合法，因为浮点表达式不是整数类型；`switch ((int)2.5)` 则符合控制表达式的类型要求。

### 6.3 贯穿执行（fall-through）

**课件第17页原例（标点统一为 ASCII）：**

```c
#include <stdio.h>

int main(void)
{
    int i = 1;
    switch (i) {
        case 0: printf("%d\t", i);
        case 1: printf("%d\t", i++);
        case 2: printf("%d\t", i++);
        case 3: printf("%d", i++);
        default: printf("\n");
    }
    printf("%d\n", i);
    return 0;
}
```

**输出：**（`\t` 在终端中是制表符，下表以可见逻辑值呈现）

```text
1    2    3
4
```

**追踪表：**

| 阶段 | 入口 / 语句 | i 进入时 | 输出 | i 执行后 |
|---|---|---:|---|---:|
| 选择入口 | `switch(i)` 命中 `case 1` | 1 | — | 1 |
| 第一次输出 | `printf(...,i++)` | 1 | `1\t` | 2 |
| 贯穿 `case 2` | `printf(...,i++)` | 2 | `2\t` | 3 |
| 贯穿 `case 3` | `printf(...,i++)` | 3 | `3` | 4 |
| 贯穿 `default` | `printf("\n")` | 4 | 换行 | 4 |
| 离开 switch | `printf("%d\n", i)` | 4 | `4\n` | 4 |

> [!important] 做题最关键的一步
> **只进行一次入口匹配**，然后沿着书写顺序向后执行。即使 `i` 在 `case 1` 中被 `i++` 修改为 2，也不会重新调度一次 `switch`。

### 6.4 `default` 不必在最后（课件第18页）

课件右侧示例可整理为：

```c
int i = 4;
switch (i) {
    default: printf("%d\t", i + 100);
    case 3:  printf("%d\t", i + 10);
    case 1:  printf("%d\t", i + 1);
    case 2:  printf("%d\t", i + 5);
}
```

因为不存在匹配的 `case 4`，从 `default` **作为入口**开始，之后依次贯穿 `case 3`、`case 1`、`case 2`：

```text
104    14    5    9
```

课件左侧示例 `i=1`、`case 1/2/3/default` 顺序排列且均无 `break`，逻辑输出则为 `2 6 11 101`。

**因此：`default` 不代表“最后一个操作”，只有位置和 `break` 才决定后续执行路径。**

### 6.5 多个标签共享分支

当多个 `case` 执行同一段操作，可以连续放置标签：

```c
switch (grade) {
    case 7:
    case 6:
        puts("middle");
        break;
    default:
        puts("other");
        break;
}
```

`case 7:`、`case 6:` 都可以进入同一条 `puts` 语句。这不是重复的 `case` 值，也不是必须插入 `break` 的位置。

### 6.6 例 4.3：用 switch 实现成绩分级

**课程版本（课件第19页，保留原有算法，排版规范化）：**

```c
#include <stdio.h>

int main(void)
{
    float x;
    printf("input the score x( 0 <= x <= 100):\n");
    scanf("%f", &x);
    if (x > 100 || x < 0)
        printf("input error!\n");
    else
        switch ((int)(x / 10)) {
            case 10: printf("excellent!\n"); break;
            case 9:  printf("excellent!\n"); break;
            case 8:  printf("good!\n"); break;
            case 7:  printf("middle!\n"); break;
            case 6:  printf("middle!\n"); break;
            default: printf("bad!\n"); break;
        }
    return 0;
}
```

**为什么使用 `(int)(x / 10)`？** `x` 是 `float`，`x / 10` 的结果是浮点类型，不能直接充当 `switch` 的控制表达式；显式转换为 `int` 后，非负成绩的小数部分被截去，从而把区间映射为整数分类值。

| 输入成绩 | `(int)(x/10)` | 命中位置 |
|---:|---:|---|
| 100 | 10 | `case 10` |
| 90 | 9 | `case 9` |
| 89.9 | 8 | `case 8` |
| 79.9 | 7 | `case 7` |
| 60 | 6 | `case 6` |
| 59.9 | 5 | `default` |

**课件给出的简写形式：**

```c
case 7:
case 6:
    printf("middle!\n");
    break;
```

> [!note] 条件适用范围
> 这里先限制 `0 <= x <= 100`，所以非负成绩除以 10 后向零截断恰好对应分级区间。不应机械把这种写法推广到所有负数分段分类题。

### 6.7 `switch` 与 `if-else` 的选择

| 场景 | 常用选择 | 原因 |
|---|---|---|
| 对单个整数/枚举值进行离散匹配 | `switch` | 分支标签清楚，可合并多个 case |
| 判断范围，例如 `x > 80 && x < 90` | `if-else` | 条件表达式直接表示范围 |
| 含多个变量或复杂逻辑条件 | `if-else` | 不受单个整型控制表达式限制 |
| 刻意利用多个标签贯穿执行 | `switch` | 可以写得简洁，但必须明确其意图 |

> [!tip] 书面题判断方法
> **离散等值匹配 → 优先考虑 `switch`；区间与复合布尔条件 → 优先考虑 `if-else`。** 这是设计经验，不是语言强制规则。

## 7. 边界与标准辨析速查

| 课件表述 / 常见理解 | 精确结论 | 优先程度 |
|---|---|---|
| “条件表达式是逻辑类型” | `if` 接受任何合法的标量表达式；零为假，非零为真 | ★★★ |
| “复合语句声明的变量只在 `{}` 内有效” | 要结合**声明点、块作用域和同名遮蔽**理解 | ★★★ |
| “嵌套 if 之间是逻辑与” | 仅能概括某些连续真分支的路径条件，不能代替完整控制流分析 | ★★★ |
| “case 会依次和控制表达式比较” | 这是理解入口选择的教学模型；控制表达式只求值一次，后面不会再次判断 | ★★★ |
| “default 是最后分支” | `default` 可以写在任何位置，且可能发生贯穿 | ★★★ |
| `case 3:` 是一个新的变量作用域 | **不是**；标签本身不自动创建一个块 | ★★ |
| `case 1: int x=1;` | C11/C17 中标签后必须有语句，直接接声明不符合该语法；可用 `{ int x=1; ... }` | ★★ |
| `break` 必须出现在每个 case 末尾 | 不是语法强制；省略会贯穿，可能是有意设计 | ★★★ |
| `switch` 可以直接处理 `float` | 不可以；控制表达式必须是整数类型 | ★★★ |
| `const int N=3; case N:` | 在 C11/C17 中 `N` 不是整数常量表达式 | ★★ |

> [!note] C23 补充（非本课程已确认要求）
> C23 对标签和声明的语法作了扩展，还引入了 `[[fallthrough]]` 属性用于显式标注有意贯穿。上面的考试分析以 C11/C17 为主要基准，不应将 C23 新语法默认视为本课程要求。

## 8. 典型错误汇总

| 错误写法 / 思路 | 问题 | 建议 |
|---|---|---|
| `if (x > 0); y++;` | 多一个空语句，`y++` 失去条件控制 | 去掉无意的分号 |
| `if (a > b) x++; y++;` | 只有 `x++` 在分支中 | 用 `{ x++; y++; }` |
| `if (a > 0) if (b > 0) ... else ...` | 容易误判 `else` 所属 | 根据最近未配对的 `if` 判断 |
| `if (90 <= x <= 100)` | C 的关系运算是左结合：先比较 `90 <= x`，再比较结果与 100 | `x >= 90 && x <= 100` |
| `switch (score / 10.0)` | 控制表达式是浮点类型 | 设计整数分类或改用 `if` |
| `case 1: ... case 1:` | 同一个 `switch` 内重复标签值 | 确保标签值唯一 |
| `switch` 中漏写 `break` | 可能贯穿执行，产生额外输出 | 明确判断是否有意贯穿 |
| 在两个 `case` 中声明同名变量而不加块 | `case` 不会自动创建作用域 | 每个分支用独立复合语句 |
| 只凭缩进分析执行路径 | 缩进不参与 C 的语法分析 | 依据关键字、花括号和分号 |

## 9. 笔试解题流程

### 9.1 `if-else` 程序阅读题

1. **确定初始值**：每个变量的类型和值是什么？
2. **恢复语法分组**：明确 `if` 的受控语句是否为块，并确定 `else` 对应哪个 `if`。
3. **从前到后求值条件**：注意短路、赋值和自增等副作用（参见 [[05 运算符与表达式]]）。
4. **标记被跳过的路径**：一旦命中 `else if` 链中的分支，就不继续检测后续条件。
5. **记录输出和最终变量值**：分开记录输出内容、执行次数、对象状态。

### 9.2 `switch` 程序阅读题

1. 计算控制表达式的**值与类型**，核对其是否为整数类型。
2. **只匹配一次**，找到起始 `case` 或 `default`。
3. 从此处按**源码顺序**向后执行，并列出所有贯穿的标签。
4. 逐行更新变量、记录输出。
5. 遇到匹配的 `break` 或主体结束才停止。

> [!important] 核心区别
> `if-else if` 是**按条件逐分支判定**；`switch` 是**先选择入口，再从入口执行一段顺序代码**。

## 12. 考前一分钟速记

> [!important] 必记结论
> 1. `表达式;` 是表达式语句，`;` 可以单独构成空语句。
> 2. `{}` 可以将多条操作组合成一条复合语句，并建立块作用域。
> 3. **同名局部变量遮蔽外层变量，但不修改外层对象。**
> 4. `if` 条件：**零为假，非零为真**；C 标准并不要求表达式必须为 `_Bool`。
> 5. **`else` 与最近、尚未配对的 `if` 配对。**
> 6. `else if` 链按顺序判断，只执行首次命中的分支。
> 7. **`switch` 只选一次入口，`case` 标签不会重新判断条件。**
> 8. 没有 `break` 时会继续执行后续标签，即贯穿执行。
> 9. **`default` 可在任意位置，不表示自动退出。**
> 10. `switch` 用整数类型表达式；`case` 用整数常量表达式且值不可重复。
